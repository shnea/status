# Golden Path

사람이 프로젝트에 적용되는 현재 기준을 읽고 검토할 수 있도록 사용자와
함께 정리하고 관리한다. Golden Path에는 사용하는 기술, 프로젝트 구조,
작업 규칙과 주요 제약을 명시하고, 개발에 사용한 스킬의 이름과 역할을
함께 정리한다.
프로젝트 소개나 대화의 장기 기억, 결정 이력을 보관하는 문서가 아니다.

## 독자와 참조 방식

-   주 독자는 사람이다. 기술과 규칙, 사용 스킬을 사람이 빠르게 이해하고
    판단할 수 있도록 작성한다.
-   에이전트는 기준을 정리·확인·갱신하는 요청을 수행하거나 특정 기준을
    확인할 필요가 있을 때 관련 내용을 조회할 수 있다.
-   일반 개발 작업을 시작할 때마다 Golden Path를 읽거나, 문서 전체를
    상시 컨텍스트에 넣고 작업하는 절차를 요구하지 않는다.
-   Golden Path의 존재나 변경을 이유로 자동 로딩, 강제 참조, 작업 전
    필수 확인 절차를 다른 에이전트 지침에 추가하지 않는다.
-   문서의 조회·정리·갱신을 일반 개발 작업의 선행 조건으로 만들지 않는다.
    반영 승인을 기다리는 동안에는 문서 변경만 보류하고, 독립적으로
    진행할 수 있는 개발 작업을 막지 않는다.

## 저장 위치와 형식

-   사용자가 지정한 경로나 프로젝트 지침에 정해진 경로가 있으면 따른다.
    별도 지정이 없고 기존 Golden Path 문서가 있으면 그 문서를 사용한다.
-   지정된 경로나 기존 문서가 없으면 작업 대상 프로젝트의
    `docs/GOLDEN_PATH.md`에 저장한다. `docs/`가 없으면 생성한다.
    스킬 설치 폴더에 저장하지 않는다.
-   새 문서는 Markdown으로 작성한다. `개발 기준` 섹션은
    `항목 | 적용 기준` 표로, `개발에 사용한 스킬` 섹션은
    `스킬명 | 역할 설명` 표로 정리한다. 기존 문서를 수정할 때는
    그 문서의 형식을 따른다.
-   작성하거나 수정하기 전에 기존 내용을 확인하고, 승인된 기준을 해당
    항목에 반영한다. 같은 기준을 여러 문서에 중복해서 관리하지 않는다.

## 지침

-   프로젝트 초기에는 개발 언어, 프레임워크, 패키지 관리자, 폴더 구조,
    명명 규칙, 주요 제약 등 프로젝트에 적용할 기준을 사용자가 정할 수
    있도록 돕는다.
-   개발 기준 항목의 포함 여부는 오래 유지되는지가 아니라 프로젝트의
    작업 방식을 정하는 기준인지로 판단한다.
-   Golden Path를 작성하거나 보여줄 때는 사용자가 빠르게 파악하고 판단할
    수 있도록 표 형태로 정리한다.
-   정해지지 않은 항목은 임의로 확정하지 않고 `미정`으로 남길 수 있다.
-   대화에서 새로운 기준이나 기존 기준의 변경을 제안할 때는 반영할
    내용을 간단히 보여주고 사용자의 동의를 받은 뒤 추가하거나 수정한다.
    사용자가 반영할 내용을 명시하여 요청했다면 다시 동의를 묻지 않는다.
-   기준이 바뀌면 해당 항목을 갱신해 현재 유효한 기준을 유지한다.
    과거 기준, 변경 내역, 결정 과정을 이력으로 누적하지 않는다.
-   프로젝트의 목적이나 기능 소개, 대화 요약, 작업 진행 상황, 일회성
    구현 판단은 Golden Path에 포함하지 않는다.
-   코딩 스타일과 테스트·검증 규칙도 프로젝트에 적용할 기준이라면
    포함할 수 있다. 실제 구현이나 테스트·검증 작업 자체는 이 스킬의
    범위에 포함하지 않는다.
-   기존 Golden Path의 기준을 사용자의 승인 없이 변경하거나 삭제하지
    않는다.

## 개발에 사용한 스킬

-   프로젝트 개발에 실제로 사용한 스킬을 같은 Golden Path 문서의
    별도 섹션에 정리한다. 단순히 설치되어 있거나 사용할 수 있다는
    이유만으로 포함하지 않는다.
-   스킬명은 식별 가능한 실제 명칭을 사용하고, 역할 설명에는 해당
    스킬이 어떤 기능을 제공하며 프로젝트에서 어떤 작업에 사용됐는지
    짧게 적는다. 사용 여부나 역할을 확인할 수 없으면 추측하지 않는다.
-   같은 스킬은 한 행으로 관리하고 필요한 경우 설명을 갱신한다.
    실행 날짜, 호출 횟수, 개별 작업 내역은 누적하지 않는다.
-   스킬 목록의 추가·수정·삭제에도 개발 기준과 같은 사용자 승인 규칙을
    적용한다.
