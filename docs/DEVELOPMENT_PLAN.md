# 상태창 개발 계획

제품 동작은 [요구사항](REQUIREMENTS.md), 기술·구조 기준은 [Golden Path](GOLDEN_PATH.md), 소스 분리 원칙은 [Agent.md](../Agent.md#소스-구조와-분리-기준)을 따른다. 이 문서는 개발 순서와 실제 확인할 조건을 관리한다.

## 첫 버전 범위

첫 공개 템플릿은 Swiss Editorial이다. 첫 버전은 요구사항의 작성·공개·관리자·통계·조건부 AI·재색인·PDF를 포함하며, 다음 단계 표는 구현 순서다. 추가 요청에 따라 운영 배포 전까지 나머지 공개 템플릿 네 개도 구현·검수한다.

## 개발 순서

| 단계 | 작업 | 확인할 결과 |
| --- | --- | --- |
| 1 | 호환 버전 고정, 실행 구성, 암호화 local ENV, DB 연결 | 같은 서비스 원점에서 화면·API·OIDC 콜백에 접근하고 실제 DB 마이그레이션과 플랫폼 연결을 확인 |
| 2 | OIDC 로그인, 계정·포트폴리오 생성, 임시저장·공개·공개 조회 | 로그인→작성→저장→공개→방문자 조회가 실제 데이터로 연결되고 동시 요청에서도 계정당 하나 유지 |
| 3 | 프로필·연락처·스킬·프로젝트·히스토리·자격, 이미지와 에디터, Swiss 화면 | 수정·재시도·순서·숨김·더보기·상세 열기·직접 상세 URL을 PC와 모바일에서 확인 |
| 4 | 단일 관리자, 이용 정지·해제, 사전·디자인·설정·통계 | 기존 세션·공개 URL·파일에서도 정지를 집행하고 관리 변경과 방문 집계를 확인 |
| 5 | 인쇄 화면·PDF, 조건부 AI와 사용자별 검색 격리, 전체 재색인 | 실제 PDF 품질과 A/B 계정 검색 격리·공개 철회·재색인 중 버전 변경을 확인 |
| 6 | 요구사항의 필수 검수, 접근성·SEO·실제 연동 확인 | 각 검수 결과를 근거와 함께 기록하고 미검증 항목을 완료로 보고하지 않음 |
| 7 | 운영 배포 전 나머지 공개 템플릿 추가 | 같은 데이터·표시 설정·주소·공개 정책을 보존하며 템플릿별 UI와 CSS 격리 확인 |

## 초기 설계에서 고정할 경계

- Spring Boot가 계정·권한·데이터 소유권·임시저장·공개·관리자·플랫폼 호출을 담당한다. Next.js는 화면 렌더링과 사용자 조작을 담당하며 브라우저에 플랫폼 서버 키를 전달하지 않는다.
- 프런트엔드·API·OIDC 콜백은 Nginx를 통해 같은 서비스 원점에 연결한다. 첫 호스트 노출 포트 30165와 내부 서비스 포트를 구분하며 필요한 추가 호스트 노출만 순서대로 배정한다.
- DB에서 회원의 issuer+subject와 포트폴리오의 소유자에 유일성을 강제한다. 저장 충돌과 공개 버전은 서버에서 검사한다.
- 스킬 사전·아이콘 목록·사용자가 선택한 스킬은 별도로 관리한다. 초기 공용 스킬과 카테고리는 데이터 초기화 작업에서 준비한다.
- 에디터는 플랫폼 패키지와 실제 체크섬을 확인한다. 클라이언트 전용 편집기와 공개 HTML 렌더링 경계를 분리하고 저장·조회·한글 입력·첨부를 실제 호스트에서 검수한다.
- 이미지 보기 변형과 보호 파일 티켓은 실제 패키지·파일 API 계약으로 확인한다. 공개 철회 이후 기존 티켓의 접근도 검수하고 필요한 경우 권한을 검사하는 호스트 중계 방식을 사용한다.
- 플랫폼의 프로젝트·환경 격리를 상태창 계정별 격리로 간주하지 않는다. 사용자별 컬렉션·색인 버전 등 실제 지원 범위에 맞는 방식을 정하고 A/B 계정으로 검증한 뒤 AI를 연결한다.
- 플랫폼 PostgreSQL 색인과 n8n Qdrant 검색은 별도 경로다. 실제 검색과 색인을 같은 저장 경로·모델·차원으로 연결하고 API 한도를 넘는 전체 교체를 단순 분할하지 않는다.
- 소스는 기능별로 모으며 의미 있는 책임 경계에서 분리한다. 새로운 파일·공통화·계층은 소스 구조 지침에 따라 검토한다.

## 실행 준비

- local SOPS 정책·암호화 ENV·제한된 평문 ACL·Docker Compose와 실제 PostgreSQL을 구성했다. dev/prod 환경은 별도로 준비한다.
- 개발 서버·빌드·코드 검사·통합 테스트·브라우저 검증은 Docker에서 수행한다. 호스트 PowerShell은 ENV 암호화와 컨테이너 실행을 제어한다.
- [실행 안내](RUNNING.md)의 명시적인 ENV 선택과 격리된 검사 명령을 사용한다.
- 최초 가입 전 관리자 식별값은 둘 다 비울 수 있다. 정상 가입 후 확인한 issuer·subject를 암호화 원본에 설정한다.
- 운영 전에는 PROD 플랫폼 설정·도메인 콜백·실제 데이터 경로를 별도로 준비하고 Search Console과 사이트맵을 공개 서비스에서 확인한다.

## 현재 구현 경계

OIDC·단일 관리자·계정당 한 포트폴리오·자동/수동 임시저장·공개본 분리·주소·미리보기·이용 정지/해제를 연결했다. 작성 화면에서 프로필의 한 줄 소개와 플랫폼 에디터 자기소개, 연락처, 대표/일반 스킬, 개인 스킬 등록·수정·신규 선택 중단, 프로젝트·히스토리·자격, 순서·항목 및 섹션 숨김을 수정할 수 있다. 프로젝트·히스토리 상세는 작성 팝업과 공개 화면에 연결했다.

표시 이름은 로고·계정 이름에 사용하고, 별도 메인 타이틀은 공개 히어로에 사용한다. 타이틀이 비어 있으면 표시 이름을 사용한다. 프로필 사진·프로젝트 대표 이미지와 별도로 HUD·Google Flat·Modern Flat·Premium Dark의 간판 이미지를 저장한다. Swiss에서는 간판을 공개하지 않으며 초안의 파일 참조를 보존한다. 공개 주소는 생성 후 변경할 수 없으며 작성 화면은 복사만 제공하고 서버도 변경 요청을 거절한다.

프로필/대표/간판 이미지는 파일 선택·드롭·붙여넣기를 지원한다. 플랫폼 비공개 업로드·명시적 장기 보존·요청 ID 재시도·소유권 검사를 연결했고, 본문에는 파일 ID를 저장한다. 보기 주소는 상태창 서버를 거쳐 현재 초안 소유권 또는 현재 공개본 포함 여부·계정 상태를 확인한다. 업로드 중 임시저장·공개를 보류한다. 실제 플랫폼의 이미지 처리와 preview/thumbnail/original 조회, 공개 철회 후 접근 차단도 검증했다.

관리자에는 공용 스킬 이름·카테고리·아이콘·별칭·신규 선택 중단, 디자인 상태·기본값, 사용자별 AI 허용, AI 사용 한도와 실제 요청 기록 집계·변경 기록을 연결했다. 방문 통계는 조회수와 일별 방문 세션을 구분하고 한국 시간으로 전체/사용자별 7·30·90일 현황을 제공한다. 본인·확인 가능한 봇·미리보기는 제외하고 같은 이벤트 재전송은 중복 제거한다. 공개 반영 수는 저장 버전별로 기록한다.

사이트맵은 최신 공개 포트폴리오·공개 프로젝트의 정규 주소만 1,000개씩 내보낸다. 공개 철회를 즉시 조회에 반영하며, 변경할 수 없는 공개 주소와 기존 별칭의 정규 주소 처리를 유지한다. robots·비공개 화면 noindex·공개 공유 메타데이터·기본 공유 이미지도 연결했다. 운영 Search Console 등록 결과나 외부 검색엔진의 반영까지 검증한 것은 아니다.

Swiss에는 4:3 이미지 중심 프로젝트와 이미지 아래 제목·요약, 작성한 자기소개의 첫 문단을 사용하는 히어로, 사진이 없는 경우의 타이포그래피 자기소개를 적용했다. 히스토리·자격의 제목과 본문 크기를 조정하고 섹션 번호·구분선·여백을 통일했다.

Swiss 외에 Dark Futuristic HUD·Google-inspired Flat·Modern Flat Minimal·Premium Dark Minimal을 각각 별도 컴포넌트와 CSS로 구현했다. HUD는 정교한 격자와 옆 패널, Google Flat은 둥근 카드와 색상 구분, Modern Flat은 왼쪽 섹션 제목과 평면적인 정보 배치, Premium Dark는 차콜 Bento 구성을 사용한다. 참고 이미지를 공개 화면에 삽입하지 않으며, 등록된 사진이 없을 때의 그래픽은 코드의 SVG로 구성한다. 관리자·작성 화면은 기존 Swiss 스타일을 유지한다.

다섯 디자인을 실제 서버의 디자인 사전·작성 설정·방문자 화면·본인 미리보기·샘플 선택 화면에 연결했다. 기존 사용자의 데이터와 Swiss 기본값은 유지하고, 신규 선택 중단 상태에서도 이미 사용하는 디자인을 저장할 수 있다. 디자인 변경만으로 공개본을 바꾸지 않으며, 공개를 명시적으로 반영한 뒤 방문자 화면에 적용한다. 섹션 순서·항목 및 섹션 숨김·슬러그·공개 상태·대표 스킬 더보기·히스토리 자세히·프로젝트 직접 URL·뒤로/앞으로 가기·키보드와 포커스 복귀를 공통 정책 아래 검증했다.

미사용 첨부는 어디에도 참조되지 않은 상태가 7일간 유지된 파일만 자동 삭제한다. 초안의 숨긴 항목·저장된 공개본·기본 공유 이미지의 파일은 보존하며, 업로드 날짜를 대기 시작일로 쓰지 않는다. 다시 참조를 저장하면 대기 시간을 초기화하고 삭제 직전에 다시 검사한다. 삭제 시작 상태를 먼저 영속화하여 새 참조·기존 업로드 요청의 복원을 차단한다. 플랫폼의 처리 결과가 불명확하면 존재 여부를 조회한 뒤 재시도하며 실패 상태와 완료 시각을 보관한다. 관리자 후보 목록에는 파일명·소유자 이름·삭제 예정 시각·재시도 대기를 표시한다. 후보 조회 자체는 자료를 변경하지 않는다. 기존 자료에도 최초 미참조 관찰부터 7일을 적용하며, 2026-10-11에 사용자가 선택한 정책을 기본 예약 작업으로 적용했다.

PDF 내보내기는 저장된 초안 또는 최근 공개본을 고정해 출력하고, 상세 포함 여부·비공개 항목 제외·짧은 출력 권한·현재 계정 상태를 검사한다. 다섯 디자인 모두 별도 A4 스타일을 사용하며 4~5쪽 검사 자료에서 한글·보호 이미지·긴 문단·클릭 가능한 링크·쪽 번호를 확인했다. 실제 사용자 세션의 PDF 다운로드 최종 확인은 별도로 남아 있다.

AI에는 서버 쿼터·사용자별 불변 색인 세대·공개 버전 검사·현재 권한 재검사·전체 중지·재색인 실행별 진행 수·실패 재시도·불명확 접수 조회 복구·이전 색인 정리를 구현했다. 실제 플랫폼의 격리된 가상 자료 색인·검색·답변을 확인했다. 현재 플랫폼 모델은 검사 문서의 공격 지시문을 따르지 않았지만 모든 공격이나 향후 모델 변경을 보장하는 검사는 아니다. 다섯 공개 화면의 PC·모바일 AI 대화·복구·철회 검사는 실제 Next.js와 격리 응답으로 확인한다. 관리자 허용 계정에만 작성자의 AI 설정 메뉴와 공개 동의 체크박스를 표시한다. 원형 로봇 버튼은 PC의 좌측 일반 패널과 모바일의 전체 화면 모달을 연다. PC에서는 배경 클릭·스크롤·키보드 조작을 허용한다. 사용자는 우측, AI는 좌측이며 대기·취소·늦은 결과 차단을 제공한다. 답변의 마크다운 굵게·목록·링크·코드·표를 렌더링한다. 현재 탭에서 포트폴리오와 방문 세션별로 대화·작성 중 질문·대기 요청 ID를 보존하며, 이동이나 재로드 시 기존 요청의 조회로만 복원한다.

시스템 설정의 서비스 이름·공지·기본 공유 이미지·파일별 한도를 연결했다. 본문 PDF·Markdown 보기와 오디오·HLS 영상 재생도 같은 출처의 현재 권한 검사 경로를 사용한다. 작성 화면의 OIDC 식별자와 관리자 목록의 내부 UUID 대신 이름·파일명·공유 주소를 표시한다. 업로드 등 변경 요청에서 서버가 CSRF 검증 실패를 구분해 반환하면 처음 검증값을 받은 계정과 현재 계정이 같을 때만 한 번 재시도한다. 같은 파일 요청 ID를 유지하며 다른 계정·정지·일반 권한 거절·반복 실패는 복구 재시도를 중단하고 입력 내용을 보존한다. 실제 잘못된 검증값의 업로드 거절은 파일 서비스 호출 전에 발생함을 서버 회귀 검사와 HTTP 요청으로 확인했다. 개발 서버 반영 후 사용자가 같은 대표이미지의 정상 등록을 확인했다.

## 2026-10-11 전체 재검토

사용자 요청에 따라 AI를 마무리한 뒤 로그인·관리자 권한·초안/공개·파일·PDF·다섯 템플릿·AI·SEO·작성 화면을 다시 검토했다. 실제 사용자 자료를 수정하거나 운영 서버에 배포하지 않았다.

| 발견한 문제 | 수정·검증 |
| --- | --- |
| 숨긴 섹션의 미완성 프로젝트·히스토리·자격이 공개를 막음 | 공개 대상 문서로 필수 제목 검사. 초안 보존·공개 API 및 직접 URL 제외·섹션을 다시 표시하면 필수 입력 거절을 PostgreSQL 회귀 검사로 확인. |
| 잘못된 연월·날짜·URL 구문이 서버 오류로 처리될 수 있음 | 입력 오류 메시지와 400 응답으로 반환. 여섯 가지 잘못된 입력과 기존 초안·버전 보존을 서버 검사로 확인. |
| 비공개 전환 후 늦은 저장 응답이 화면의 공개 상태를 되돌림 | 최신 공개·AI 설정을 유지하고 저장된 내용만 반영. PC·모바일에서 응답 순서를 지연시켜 재현한 뒤 수정 결과를 확인. 서버 공개 상태는 이 문제에서도 비공개로 유지됐음. |

AI는 다섯 템플릿 × PC·모바일에서 대화·마크다운·취소·늦은 결과 차단·모바일 근거 이동/재로드 복원·방문 세션별 격리를 확인했다. PC의 비모달 채팅과 프로젝트 모달을 함께 연 상태에서 모바일로 전환했다가 돌아온 경우의 포커스·Escape·배경 스크롤도 확인했다. 마지막 전체 검사 결과는 서버 55개 통과(외부 opt-in 3개 제외), Chromium 78개 통과, 프런트엔드 정적 검사·포맷·최적화 빌드 통과다. 다섯 디자인의 PDF를 각각 4쪽 생성하고 20쪽을 시각 검수했다. 개발 서버 반영 후 상태 검사·로그인·템플릿 목록과 다섯 샘플 페이지는 모두 200으로 응답했다.

현재 검토와 자동 검사 범위에서 미해결 중대 기능 오류는 발견하지 못했다. 앱 코드는 기능별 책임과 템플릿별 컴포넌트/CSS 경계를 유지하며, 이번 수정에 새 전달 계층이나 임의의 파일 분할을 추가하지 않았다.

운영 배포는 사용자가 다음 작업으로 미뤘다. 다음에는 실제 사용자 세션의 PDF 다운로드, 실제 모델 작업의 취소 확인, 서버/PROD 설정·최종 이미지·배포 후 OIDC 및 HTTPS·공개/비공개 접근을 확인한다. 실제 사용자 탭은 이번 재검토에서 브라우저 자동화 연결을 초기화하지 못해 조작하지 않았다. 실제 모델을 새로 호출하는 취소 검사는 수행하지 않았으며, 취소 UI·서버 경합·플랫폼 취소 요청 계약은 격리 검사로 확인했다. Golden Path와 ENV 규칙은 이번에 변경하지 않았다.

## 자기소개 섹션 순서 변경 (2026-10-11)

설정의 섹션 순서·표시에 자기소개를 포함했다. 다섯 템플릿의 본문과 상단 메뉴, 작성자 미리보기, PDF는 같은 순서를 따른다. 자기소개를 숨겨도 초안 내용은 보존하며 공개 API·AI 검색·공개 화면의 소개 발췌·PDF에서 제외한다. 기존 네 섹션 자료는 과거 화면의 위치를 유지하여 읽고, 순서를 저장할 때 다섯 섹션으로 반영한다. 조회만으로 저장된 초안·공개본을 수정하지 않는다.

Docker에서 서버 57개 통과(외부 opt-in 3개 제외), PC·모바일 Chromium 88개 통과, 프런트엔드 정적 검사·포맷·최적화 빌드와 다섯 템플릿 PDF 검사를 확인했다. 자기소개의 처음·중간·마지막 배치, 숨김 후 재표시, 저장·재조회, 공개본 분리와 기존 자료 호환을 포함한다.

## HUD 화면 개선 (2026-10-11)

HUD의 히어로를 큰 타이틀·배경 이미지·격자·궤도선이 연결된 구성으로 변경했다. 기본 장면은 별도 SVG 컴포넌트에 두고, 사용자 간판 이미지가 있으면 같은 배경과 프레임을 적용한다. 상단 탐색·프로젝트 3열·섹션 순서·공개 정책은 보존하며 프로젝트·사진·스킬·히스토리에도 시안 코너와 선 규칙을 적용했다. 다른 네 템플릿과 PDF 스타일은 변경하지 않았다.

Docker에서 프런트엔드 정적 검사·타입·포맷·최적화 빌드와 PC·모바일 Chromium 88개 검사를 통과했다. 별도 브라우저 검수에서는 보호 이미지 응답을 격리하여 간판·프로필 이미지, 자기소개 6문단, 프로젝트 13개, 사용자 지정 섹션 순서, 320/390/768/1440px 너비와 동작 감소를 확인했다. 초기 검사 두 건은 개발 서버 재시작과 겹쳐 화면을 불러오지 못했으며, 서버 재기동 후 전체 88개를 다시 통과했다.

현재 적용 대상은 개발 서버이며 디자인 검토 후 운영 배포를 진행한다.

미사용 첨부는 어디에도 참조되지 않은 상태가 7일간 유지된 파일만 자동 삭제한다. 초안의 숨긴 항목·저장된 공개본·기본 공유 이미지의 파일은 보존하며, 업로드 날짜를 대기 시작일로 쓰지 않는다. 다시 참조를 저장하면 대기 시간을 초기화하고 삭제 직전에 다시 검사한다. 삭제 시작 상태를 먼저 영속화하여 새 참조·기존 업로드 요청의 복원을 차단한다. 플랫폼의 처리 결과가 불명확하면 존재 여부를 조회한 뒤 재시도하며 실패 상태와 완료 시각을 보관한다. 기본 서버 검사에 대기 시작·7일 경계·숨긴 본문/공개본/공유 이미지 보존·스캔 사이 참조 재등록·이전 업로드 요청 차단·실패 재시도·회원 편집 잠금 경합을 포함했다. HTTP 검사에서는 삭제 응답 유실 후 재조회와 알 수 없는 404/403의 실패 처리를 확인했다. 실제 플랫폼에서는 생성한 검사 이미지 삭제와 재조회를 별도로 통과했다.
