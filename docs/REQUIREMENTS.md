# 상태창 요구사항

상태창은 누구나 OIDC 로그인 후 자신의 포트폴리오를 작성하고 공유할 수 있는 서비스다. 계정당 포트폴리오는 반드시 하나다. 아래 내용은 합의한 제품 요구사항이며, 수치와 기본 동작은 나머지 항목에 대한 사용자 위임에 따라 정한 초기 기준이다. 기능 구현 완료를 뜻하지 않는다.

## 1. 서비스와 범위

| 항목 | 기준 |
| --- | --- |
| 프로젝트명 | 상태창 |
| 서비스 도메인 | status.shnea.kr |
| Git 원격 | https://github.com/shnea/status.git |
| 백엔드 | [Golden Path](GOLDEN_PATH.md)의 Spring Boot·Kotlin 기준 |
| 가입 | 누구나 OIDC 로그인 후 즉시 이용. 초대·가입 승인 없음 |
| 포트폴리오 수 | 계정당 1개. 디자인별로 별도 포트폴리오를 만들지 않음 |
| 초기 공개 디자인 | Swiss Editorial Portfolio |
| 작성·관리 화면 | Swiss Editorial 스타일 고정 |
| 첫 버전 메인 페이지 | 서비스 소개·로그인·작성 화면 진입. 전체 사용자 목록·검색은 초기 범위에서 제외 |
| 후속 공개 디자인 | Dark Futuristic HUD, Google-inspired Flat, Modern Flat Minimal, Premium Dark Minimal |

첫 버전 기능에는 프로필·스킬·프로젝트·히스토리·자격/인증, 임시저장·미리보기·공개, 관리자, 통계, 조건부 AI 질의응답, PDF 내보내기, AI 재색인을 포함한다. 초기 Swiss 이후의 추가 요청에 따라 운영 배포 전 범위에 나머지 네 템플릿도 포함한다.

## 2. 계정과 권한

- 일반 이용자는 플랫폼 OIDC로 로그인한다. 첫 정상 로그인에서 상태창 회원과 하나의 비공개 포트폴리오를 생성한다.
- 회원은 검증한 issuer와 subject 조합으로 식별한다. 이메일·닉네임으로 계정을 합치거나 권한을 판단하지 않는다.
- 동시 첫 로그인이나 요청 재전송으로 회원·포트폴리오가 중복 생성되지 않아야 한다.
- 로그인된 상태에서 메인 시작하기·플랫폼 로그인 버튼을 누르면 현재 세션으로 작성 화면에 바로 진입한다. 동시 세션 속성 저장이 중복 오류로 화면 이동을 막지 않아야 한다.
- 일반 회원은 자기 데이터만 조회·수정·미리보기·PDF 출력할 수 있다. 방문자는 현재 공개 데이터만 조회한다.
- 슈퍼관리자는 한 명이다. 검증된 OIDC issuer와 subject가 서버의 ADMIN_OIDC_ISSUER와 ADMIN_OIDC_SUBJECT 모두에 정확히 일치해야 한다.
- 관리자 지정값은 회원가입 후 설정할 수 있다. 둘 다 빈 경우 일반 로그인·가입은 가능하되 슈퍼관리자는 없다. 한쪽만 비어 있으면 잘못된 설정으로 실행 초기에 실패한다.
- 첫 가입자·특정 이메일·닉네임을 자동으로 관리자로 승격하지 않는다. 일반 이용자가 관리자 환경변수를 설정하는 화면도 제공하지 않는다.
- 관리자 설정 변경 후 새 설정이 적용되면 이전 관리자 세션도 이전 권한을 유지하지 않는다.

### 이용 정지와 해제

- 슈퍼관리자는 사용자 검색 후 정지 사유를 남기고 이용 정지·해제할 수 있다.
- 정지되면 기존 세션을 포함해 작성·수정·미리보기·PDF 출력·AI 사용을 제한한다. 공개 포트폴리오와 상세 페이지도 노출하지 않는다.
- 정지된 사용자는 자신의 제한 상태 안내와 로그아웃만 이용할 수 있다.
- 정지는 삭제가 아니다. 작성 데이터는 보존하고 관리자에게 처리자·대상·사유·시각을 기록한다.
- 해제 후 작성은 가능하며 공개 재개는 소유자가 선택한다. 기존 데이터·주소·디자인은 보존한다.
- 유일한 슈퍼관리자를 자기 자신이 정지하는 기능은 제공하지 않는다.
- 관리자 사용자 관리는 계정 상태·운영 설정과 공개 정보 확인이 기본이다. 타인의 비공개 초안을 일반 관리 화면에 노출하지 않는다.

## 3. 공유 주소

- 공개 주소는 /@slug, 프로젝트 상세 주소는 /@slug/projects/{projectId} 형태로 제공한다.
- 표시 이름·닉네임과 공유 주소는 별개다. 최초 포트폴리오 생성 시 서버가 유일한 주소를 발급하며 이후 변경할 수 없다. 화면의 변경 입력을 없애고 서버도 변경 요청을 거절한다.
- 이미 발급한 현재 주소와 과거 별칭은 보존한다. 과거 별칭은 현재 주소로 연결하며 다른 계정에 재할당하지 않는다.
- 공유 URL 복사 기능을 제공한다. 비공개인 경우 복사는 가능하더라도 외부에서 열리지 않는 상태임을 명확히 표시한다.
- 존재하지 않거나 공개되지 않은 포트폴리오·프로젝트는 방문자에게 내용을 제공하지 않는다. 미리보기 URL을 공개 공유 URL로 사용하지 않는다.

## 4. 임시저장과 공개본

- 편집용 임시저장본과 현재 공개본을 분리한다. 편집·자동 저장만으로 공개본을 변경하지 않는다.
- 입력이 2초간 멈추면 자동 임시저장을 시도한다. 수동 임시저장도 제공한다.
- 저장 중·저장됨·저장 실패 상태를 표시한다. 실패 시 현재 입력을 보존하고 재시도를 제공한다.
- 저장 전 화면 이탈·로그아웃이나 여러 탭의 수정 충돌에서 최신 입력을 조용히 덮어쓰지 않는다.
- 공개 반영은 일관된 하나의 버전을 반영한다. 프로필·항목·순서·숨김·디자인이 부분적으로 섞여 공개되지 않도록 한다. 필수 제목 검사는 실제 공개 대상에만 적용하며, 숨긴 섹션의 미완성 항목은 초안에 보존하고 공개를 막지 않는다.
- 미리보기는 현재 임시저장 내용과 선택한 공개 템플릿을 보여준다. 본인만 접근하며 검색엔진 노출을 금지한다.
- 섹션 전체와 개별 프로젝트·히스토리·자격/인증을 숨길 수 있다. 연락처/링크도 개별 공개 여부를 둔다.
- 항목·섹션 숨김 편집은 공개 반영 시 적용한다. 포트폴리오 전체 비공개, AI 공개 동의 철회, 관리자 정지는 즉시 적용한다. 늦게 도착한 임시저장 응답이 더 최근의 공개·AI 설정 표시를 되돌리지 않아야 한다.
- 공개본에서 숨겨진 데이터는 공개 API·직접 상세 조회·AI 검색·공유 메타데이터에서도 제외한다.
- 공개를 철회한 자료를 기존 파일 보기 링크·검색 색인·답변 캐시가 계속 노출하지 않도록 새 접근을 차단하고 파생 자료를 정리한다.

## 5. 프로필과 링크

- 표시 이름 또는 닉네임, 메인 타이틀, 한 줄 소개, 긴 자기소개, 프로필 이미지를 작성한다. 상단 로고는 표시 이름 전체를 한 번만 사용하며 약자·잘린 이름과 전체 이름을 중복 표시하지 않는다. 메인 타이틀은 히어로의 큰 제목에 사용한다. 메인 타이틀을 비워두면 표시 이름을 사용한다.
- HUD·Google-inspired Flat·Modern Flat Minimal·Premium Dark Minimal에서는 프로필 이미지와 별도의 간판 이미지를 등록·교체·제거한다. 파일 선택·드롭·붙여넣기·동일 소유권 검사를 적용한다. 이미지와 타이틀은 임시저장·미리보기·명시 공개 반영·PDF에 연결하며 디자인 변경 시 보존한다. Swiss에서는 간판 이미지를 표시하거나 공개 파일로 노출하지 않는다.
- 긴 자기소개는 한 줄 소개와 별도 필드이며 플랫폼 에디터로 작성한다. 서식·문단·목록·표 등을 구조화된 문서로 저장하며 자동/수동 임시저장·미리보기·공개 반영·PDF·AI 공개 데이터 범위에 함께 적용한다.
- 닉네임과 공유 주소를 분리하고, 프로필 이미지가 없을 때 기본 표시를 제공한다.
- 연락처/링크는 여러 개 추가할 수 있다. 유형·라벨·값·아이콘·순서·공개 여부를 관리한다.
- 기본 유형은 이메일·전화·웹 링크다. 유형에 맞는 입력 검사와 클릭 동작을 적용한다.
- 프로젝트 외부 링크도 동일한 입력 원칙을 사용하고 공개 화면에는 칩/배지 형태로 표시한다.
- 외부 링크 칩을 클릭하면 해당 링크로 이동한다. 프로젝트 상세 이동과 클릭 동작이 충돌하지 않아야 한다.
- 링크 개수에 임의의 작은 제품 제한을 두지 않되, API 요청 크기와 유효성은 검사한다.

## 6. 스킬

- 공용 스킬 사전은 관리자, 개인 스킬은 해당 소유자가 관리한다.
- 스킬명·카테고리는 필수이며 아이콘 선택은 선택 사항이다. 공용 스킬의 별칭과 사용 중단 상태를 관리한다.
- 사용자 목록은 대표 스킬과 일반 스킬로 나눈다. 같은 스킬을 두 목록에 중복 표시하지 않는다.
- 대표 스킬은 최대 10개이며 백엔드에서도 검사한다. 일반 스킬은 제품 정책상 개수 제한을 두지 않는다.
- 대표↔일반 이동은 드래그앤드롭으로 제공하고 모바일·키보드용 이동 동작도 제공한다.
- 각 목록 안의 수동 순서 지정은 하지 않는다. 카테고리로 묶고 이름순으로 자동 정렬한다.
- 초기 정렬은 한글 가나다순·영문 대소문자 무시·숫자 자연 정렬을 지원하는 동일한 기준을 사용한다. 카테고리도 이름순으로 표시하며 미분류는 기타로 마지막에 둔다.
- 대표 스킬이 이미 10개라면 추가 이동을 거부하고 안내한다. 기존 대표 스킬을 임의로 빼지 않는다.
- 개인 스킬은 해당 사용자만 선택할 수 있는 사전 항목이며, 선택하면 공개 포트폴리오에 표시할 수 있다.
- 이름의 앞뒤 공백과 영문 대소문자를 정규화한 뒤 공용·개인 이름이 겹치면 본인에게는 개인 항목을 우선 표시한다. 다른 사람의 사전에는 영향이 없다.
- 기존 프로젝트의 스킬 연결은 안정적인 식별자로 보존한다. 이름 충돌이나 공용 사전의 수정 때문에 연결을 조용히 삭제하지 않는다.
- 관리자 사전에서 사용 중인 스킬을 중단해도 기존 사용자의 표시를 임의로 없애지 않는다. 신규 선택 중단과 기존 사용은 구분한다.

### 검색과 직접 등록

- 작성자는 공용 스킬과 본인의 개인 스킬을 검색한다. 결과를 선택하면 일반 스킬 목록에 바로 추가하며 이미 선택한 항목을 중복 추가하지 않는다.
- 검색 결과가 없으면 검색어가 입력된 개인 스킬 등록 화면을 연다. 스킬명·카테고리와 선택 사항인 아이콘으로 등록한다.
- 새 개인 스킬은 등록 후 일반 스킬 목록에 바로 추가한다. 임시저장·공개 반영 정책은 다른 편집 내용과 동일하다.
- 스킬 사전과 아이콘 목록은 별도로 관리하되, 사용자 결정에 따라 Simple Icons 전체 목록을 검색 가능한 공용 스킬로도 등록한다. 같은 정규화 이름은 중복 등록하지 않고 기존 스킬의 식별자·이름·카테고리·아이콘·사용 중단 설정과 개인 스킬 우선 정책을 유지한다. 기본 분류가 없는 새 항목은 브랜드 · 도구로 등록하며 관리자가 변경할 수 있다.
- 수천 개의 항목을 지원하도록 스킬·아이콘 검색 결과를 페이지 단위로 조회한다. 전체 목록과 모든 SVG를 처음부터 한꺼번에 불러오지 않는다.

### 아이콘 선택과 배지

- 공용 스킬과 개인 스킬은 같은 아이콘 선택기를 사용한다. 브랜드 로고 검색·기본 아이콘 선택·약자 배지를 제공한다.
- 브랜드 로고는 Simple Icons 목록을 기본으로 사용하며 Simple Icons CDN의 식별자로 연결한다. 스킬의 표시 이름과 아이콘 식별자는 분리한다.
- 기본 아이콘은 Lucide로 통일한다. 시스템 설계·협업 등 고유 브랜드 로고가 없는 스킬에 의미가 맞는 기본 아이콘을 선택할 수 있다.
- 아이콘을 선택하지 않으면 표시명에서 짧은 약자를 만들어 배지를 자동 생성한다. 예를 들어 MyTool은 MT로 표시한다. 아이콘 부재가 스킬 등록을 막지 않는다.
- 개인 스킬 등록의 외부 아이콘 URL 직접 입력은 초기 범위에서 제외한다.
- 관리자는 공용 스킬의 아이콘 연결을 수정하고 필요한 누락 로고를 공용 아이콘 목록에 추가할 수 있다.
- 자동 연결은 확인된 이름·별칭 매핑에만 적용한다. 이름이 비슷하다는 이유만으로 다른 브랜드 로고를 확정하지 않는다.
- 아이콘 출처·식별자·원본 색상·허용되는 표현 변형을 공통 정보로 관리한다. 모든 로고를 임의로 변형하거나 일괄 재색상하지 않는다.
- 아이콘 영역의 크기·정렬·여백은 공통 규격을 사용하고 색상·크기·배지 배경·테두리 등 구체적인 표현은 템플릿이 결정한다.
- 원본 아이콘 자산은 공유할 수 있으나 배지 컴포넌트와 CSS는 템플릿별로 분리한다. 단색 변형을 사용할 수 없는 로고는 원본 색상을 유지하며 배지로 조화를 맞춘다.
- 아이콘이 목록에서 제거되거나 불러오기에 실패하면 약자 배지로 대체한다. 스킬명·카테고리·프로젝트 연결은 유지한다.
- 공개 화면에서는 해당 포트폴리오가 실제 사용하는 아이콘만 불러온다.

### 방문자 표시

- 처음에는 대표 스킬만 카테고리별로 묶어 아이콘 배지와 스킬명으로 표시한다.
- 일반 스킬이 있을 때 더보기를 제공한다. 펼치면 공개본에서 선택한 대표·일반 스킬 전체를 카테고리별·이름순으로 중복 없이 표시한다.
- 더보기는 공용 사전 전체나 선택하지 않은 개인 스킬을 표시하지 않는다. 섹션 숨김과 공개 범위는 펼친 상태에도 동일하게 적용한다.
- 일반 스킬이 없으면 더보기 버튼을 생략한다. 펼친 목록은 다시 접을 수 있다.

| 필드 | 요구사항 |

- 작성자 목록은 리스트 형태이며 드래그앤드롭으로 순서를 바꾼다. 대체 이동 버튼도 제공한다.

- 방문자 목록에는 대표 이미지·제목·요약·외부 링크 칩을 표시한다. 대표 이미지가 없어도 레이아웃이 깨지지 않는다.

- 외부 링크 칩은 해당 연락처·링크 동작만 수행한다. 같은 클릭으로 프로젝트 상세가 함께 열리지 않는다.
- 프로젝트 상세 URL은 유지한다. 직접 공유·새로고침·새 탭 접근에서도 같은 상세 내용을 선택한 공개 템플릿으로 제공한다.
- 목록에서 연 상세는 브라우저 뒤로 가기로 닫고 기존 목록 위치로 돌아갈 수 있어야 한다.
- 상세 표시 방식과 직접 URL 접근 모두 공개·숨김·정지 조건을 적용한다.
- 편집 실패·이미지 업로드 실패 시 입력을 잃지 않으며 재시도할 수 있다.

- 자격 ID의 공개 여부를 별도로 관리한다. 숨긴 ID는 AI 검색에서도 제외한다.
- 표시 순서와 개별 숨김을 지원한다.

## 9. 디자인과 화면 설정

- 자기소개·스킬·프로젝트·히스토리·자격/인증 섹션의 순서와 표시 여부를 사용자가 설정한다. 자기소개도 드래그앤드롭과 이동 버튼으로 배치하며 공개 화면·미리보기·PDF에 같은 순서를 적용한다. 기존 네 섹션 문서는 기존 자기소개 배치를 유지하도록 읽고, 저장할 때 다섯 섹션 설정을 기록한다. 숨긴 자기소개는 초안에 보존하되 공개 API·AI 검색·PDF와 히어로 요약에서 제외한다.
- 공개 템플릿을 변경해도 작성 데이터·섹션 순서·숨김·항목 순서·공유 URL·공개 상태는 유지한다.
- 관리자·작성 화면은 Swiss Editorial 스타일로 고정한다. 공개 미리보기와 방문자 화면만 선택한 템플릿으로 표시한다.
- 데이터와 공개 정책은 공통으로 관리하고, 템플릿별 레이아웃·화면 컴포넌트·스타일은 격리한다.
- 한 템플릿의 CSS 수정이 다른 템플릿에 영향을 주지 않아야 한다. 색상만 바꾸는 방식으로 다섯 콘셉트를 구현하지 않는다.
- 공통으로 공유할 수 있는 것은 데이터 계약·동작 로직 등이다. 구체적인 프론트엔드 기술과 구성 방식은 구현 설계에서 정한다.
- 관리자 템플릿 관리는 목록·미리보기·기본값·신규 선택 가능 여부를 포함한다. 신규 선택 중단만으로 기존 사용자의 디자인을 강제 변경하지 않는다.
- 코드 없이 새 디자인을 만드는 템플릿 제작기는 초기 범위에 포함하지 않는다.
- 메인의 샘플 포트폴리오 보기는 로그인 없이 템플릿 선택 화면을 연다. 구현되어 신규 선택 가능한 템플릿만 목록에 표시하고, 선택하면 실제 템플릿의 예시 포트폴리오를 연다. Swiss·Dark Futuristic HUD·Google-inspired Flat·Modern Flat Minimal·Premium Dark Minimal을 구현했으며, 관리자 상태에 따라 선택 목록을 표시하고 샘플에서 목록으로 돌아갈 수 있다.
- 모든 템플릿은 모바일·키보드 접근·명확한 포커스·읽기 쉬운 대비·동작 감소 설정을 지원한다.
- 더보기·자세히·닫기 동작은 모든 템플릿에서 알아볼 수 있어야 한다. 모달·옆 패널은 키보드 조작·Escape로 닫기·닫은 뒤 진입 위치로 포커스 복귀를 지원한다.

### UI 문구

- 연락처 칩과 스킬 배지는 둥근 모서리를 사용한다.
- 계정·파일·작업의 내부 UUID와 OIDC issuer·subject 등 이용자가 조작할 필요 없는 식별 정보는 화면에 표시하지 않는다. 관리 대상은 이름·공유 주소·파일명으로 구분하고, 내부 식별자는 요청 처리에만 사용한다.
- 메인·공개 포트폴리오·작성·관리자 화면 모두 타이틀은 허용하되, 꼭 필요하지 않은 설명 문구를 붙이지 않는다. 제목 아래에 임의로 서비스 홍보·소개 문장을 추가하지 않는다.
- 예를 들어 프로젝트 제목 아래에 진행한 프로젝트를 확인해보세요 같은 장식적 안내 문장을 표시하지 않는다.
- 입력 형식·공개 범위·저장 실패 등 사용자의 판단과 조작에 필요한 안내만 짧게 제공한다.
- 사용자가 작성한 한 줄 소개·프로젝트 요약·히스토리 요약은 콘텐츠이므로 이 규칙으로 생략하지 않는다. 검색엔진용 설명 메타데이터도 별도로 유지한다.

- 네온 발광, HUD 요소, 과도한 3D 효과 제외.

## 10. AI 질의응답

- 관리자 사용자별 AI 허용은 기본 OFF다. 사용자 본인의 AI 공개 동의도 기본 OFF다. 관리자가 허용한 계정에만 작성 화면의 AI 관리 메뉴와 설정의 공개 사용 체크박스를 표시한다. 서버도 관리자 허용 없이 사용자 공개 동의를 켜는 요청을 거절한다.
- 공개 화면의 우측 하단에 원형 로봇 버튼을 표시한다. 클릭하면 PC에서 좌측 채팅 패널, 모바일에서 전체 화면 채팅을 연다. PC에서는 채팅이 열린 상태로 포트폴리오의 클릭·키보드 조작·스크롤을 할 수 있으며, 모바일에서는 채팅에 포커스를 유지하고 배경 조작을 막는다. 사용자 말풍선은 우측, AI 말풍선은 좌측에 배치한다. 답변 대기 표시·취소·닫기·키보드 포커스 복귀를 제공한다.
- 취소는 해당 방문 세션의 요청만 대상으로 한다. 접수 중·접수 유실·늦은 완료 결과에서도 새 모델 요청을 만들지 않으며 취소한 답변을 대화에 추가하지 않는다. 플랫폼 취소 요청과 실제 종료 확인을 구분해 표시한다.
- 두 조건 모두 ON이고 계정이 활성·포트폴리오가 공개 상태일 때만 방문자가 질문할 수 있다.
- 방문자는 로그인 없이 이용할 수 있다. 작성 데이터 변경·문서 작성 기능이 아닌 해당 포트폴리오에 대한 읽기 전용 질의응답이다.
- 검색 자료는 해당 사용자에게 속한 현재 공개 데이터만 사용한다. 초안·숨긴 항목·비공개 연락처·다른 사용자 데이터는 제외한다.
- 답변에 사용한 프로젝트·히스토리 등 근거 링크를 제공한다. 근거가 없으면 확인할 수 없다고 답변한다. AI 답변은 마크다운의 굵게·목록·링크·코드·표를 렌더링한다. 원시 HTML·실행 가능한 링크·외부 이미지 자동 로딩을 허용하지 않는다.
- 자료 안의 지시문을 시스템 명령으로 따르지 않는다. 자료 내용으로 권한이나 검색 대상 사용자를 바꿀 수 없어야 한다.
- 관리자 OFF·사용자 동의 철회·전체 비공개·정지 시 기존 대화에서도 새 질문을 차단한다. 실행 중 결과 반환 전에도 현재 권한을 확인한다.
- 대화 전문은 기본적으로 서버에 영구 보관하지 않는다. 현재 탭의 세션 저장소에서 포트폴리오·방문 세션별로 대화와 작성 중 질문을 보존한다. 모바일에서 근거 링크를 열고 돌아오거나 페이지가 다시 생성돼도 복원한다. 대기 중 요청은 같은 ID의 상태만 확인하며 모델을 다시 실행하지 않는다. 다른 포트폴리오·새 방문 세션과 섞지 않으며 새 대화로 초기화할 수 있다. 소유자와 관리자에게 방문자의 대화 전문을 제공하지 않는다.
- 운영 기록은 사용자·요청 식별·상태·지연·검증 가능한 사용량 등의 최소 정보로 제한한다. 질문·답변 전문·비밀값을 로그에 남기지 않는다.
- 초기 제한은 방문 세션당 하루 10회, 포트폴리오당 하루 100회, 서비스 전체 하루 1,000회 및 방문 세션당 분당 3회다. 관리자 설정으로 변경 가능하며 서버에서 실제 집행한다.
- 익명 세션 재생성만으로 무제한 호출되지 않도록 추가 요청 빈도 제어를 적용한다. 제한·공급자 장애·시간 초과는 각각 구분해 표시한다.
- 자동 유료 공급자 전환이나 무한 재시도를 하지 않는다. 플랫폼의 추정·미검증 사용량을 실제 청구 비용이나 남은 토큰으로 단정하지 않는다.

### 검색 자료 갱신과 재색인

- 공개 반영·항목 숨김·삭제에 맞춰 해당 사용자 자료를 갱신한다. AI가 꺼진 사용자의 새 색인·모델 실행을 기본적으로 수행하지 않는다.
- 관리자 AI 관리에서 사용자별 재색인과 전체 재색인을 제공한다.
- 전체 대상은 활성 계정·공개 포트폴리오·관리자 허용·사용자 동의 조건을 모두 충족한 사용자다.
- 진행 상태·대상 수·완료 수·실패 수·실패 사유·실패 대상 재시도를 제공하고 같은 대상의 중복 실행을 막는다.
- 새 색인 준비 중에는 현재 공개 범위에 속하는 기존 자료만 사용할 수 있다. 갱신이 지연돼도 접근을 철회한 자료를 모델 입력이나 답변에 포함하지 않는다.
- 사용자별 소유권과 검색 범위를 서버에서 결정하며, 브라우저가 임의의 검색 대상 범위를 지정하지 못하게 한다.
- 재색인 도중 새 공개본이 생기면 이전 작업 결과가 최신 공개본을 덮어쓰지 않는다.
- 플랫폼의 컬렉션 전체 교체와 요청 크기 제한을 고려해 실제 지원 API에 맞게 구현한다. 단순 분할 호출로 기존 데이터가 지워지는 방식은 사용하지 않는다.

## 12. 에디터와 파일

- 프로젝트·히스토리 본문은 SHNEA 플랫폼 에디터의 구조화된 JSON으로 저장한다.
- 플랫폼 서버 키는 상태창 서버에서만 사용한다. 본문 저장·파일 소유권·공개 여부·입력 검사는 상태창 책임이다.
- 본문에는 fileId를 보관하고 만료되는 파일 보기 URL을 영구 저장하지 않는다.
- 사용자별 총 업로드 용량 제한과 할당량 화면은 초기 범위에서 제외한다.
- 파일 하나의 형식·크기는 검사한다. 초기 프로필·간판·프로젝트 대표 이미지 허용 형식은 JPEG·PNG·WebP, 최대 10 MiB다. 플랫폼 제한이 더 낮으면 그 제한을 함께 따른다.
- 본문 첨부는 에디터·플랫폼이 지원하는 형식 안에서 서비스 허용 목록과 파일별 한도를 정한다. 영상의 외부 도메인 재생 등 추가 연동이 필요한 형식을 자동으로 지원 완료로 취급하지 않는다.
- 초안·비공개 첨부를 플랫폼 기본 공개 상태로 방치하지 않는다. 공개·정지·삭제 상태를 파일 접근에도 적용한다.
- 포트폴리오 첨부는 장기 보존 정책을 사용한다. 플랫폼의 default 보존 코드를 영구 보관으로 간주하지 않는다.
- 교체·삭제·저장하지 않은 편집의 첨부는 어디에도 참조되지 않은 상태가 7일간 유지된 경우에만 자동 삭제한다. 초안의 숨긴 항목·저장된 공개본·기본 공유 이미지에서 사용 중인 파일을 보존한다.
- 미참조 최초 관찰부터 대기하며 업로드 날짜로 소급하지 않는다. 다시 참조를 저장하면 대기 시간을 초기화하고, 삭제 직전에 현재 참조를 재검사한다.
- 삭제 시작 이후에는 새 참조·기존 업로드 재시도로 파일을 되살리지 않는다. 플랫폼의 삭제 결과가 불명확하면 존재 여부 확인 후 재시도하며 실패와 완료 기록을 보관한다.
- 본문에서 첨부를 제거하는 것과 파일 원본을 삭제하는 것을 분리한다.
- 업로드 취소·재시도·클립보드 접근 불가·지원하지 않는 형식·크기 초과·처리 중 상태를 사용자에게 안내한다.

## 13. PDF 내보내기

- 소유자의 작성 화면에서만 제공한다. 타인의 포트폴리오를 출력하는 공개 버튼은 두지 않는다.
- 현재 공개본 또는 저장된 임시저장본을 선택한다. 미저장 변경이 있으면 먼저 저장하거나 저장 실패를 해결해야 한다.
- 선택한 버전의 섹션 순서·숨김·항목 순서·템플릿을 적용한다. 숨김 내용을 우회해 포함시키지 않는다.
- 기본은 프로젝트 요약과 상세 페이지 링크를 포함한다. 작성자는 프로젝트 상세 내용 포함을 추가로 선택할 수 있다.
- 공개되지 않은 초안 프로젝트에 유효한 공개 링크가 있는 것처럼 표시하지 않는다.
- 템플릿의 분위기를 유지하는 A4 인쇄 전용 배치를 사용하고, 링크는 PDF에서도 클릭 가능하게 유지한다.
- 애니메이션·AI 채팅·편집 버튼은 제외한다. 긴 내용·페이지 나눔·한글 폰트·이미지 잘림을 미리보기에서 확인할 수 있어야 한다.
- 생성 실패를 알리고 다시 시도할 수 있다. 비공개 PDF 결과와 임시 파일은 소유자만 접근 가능하며 영구 공개 URL로 제공하지 않는다.

### Search Console

- 기존 shnea.kr 소유권을 활용하고 하위 도메인을 개별 속성으로 추가하는 운영 방식을 따른다. 상태창은 https://status.shnea.kr/ URL 접두어 속성으로 관리한다.
- 기존 인증된 상위 속성의 권한으로 자동 확인되는지 먼저 확인한다. 자동 확인되면 상태창의 별도 확인 태그는 필수가 아니다.
- 별도 HTML 태그 확인이 필요한 경우, 제공된 확인 값이 해당 소유자의 확인 화면 안내와 일치하는지 확인하고 런타임 GOOGLE_SITE_VERIFICATION 값으로 공개 메인 페이지에 연결한다.
- 기존 도메인 속성의 DNS 인증을 유지하며, 사이트맵·검색엔진 노출 정책과 소유권 확인을 구분한다.
- 실제 값은 ENV 지침에 따라 관리하고 코드·예시·요구사항에 하드코딩하지 않는다.

## 15. 실행 환경과 포트

- 환경은 local / dev / prod로 구분하고 [ENV 관리 지침](ENV_GUIDELINES.md)을 적용한다.
- 제공된 localhost 콜백 설정은 local 실행에서 플랫폼 DEV 환경으로 연결하는 용도다. 상태창 실행 환경 이름과 플랫폼 환경 UUID를 혼동하지 않는다.
- 앱의 첫 호스트 노출 포트는 30165이고 Nginx를 통해 도메인으로 접근한다.
- 추가 호스트 노출이 필요한 서비스는 30166부터 1씩 증가해 배정한다. DB가 첫 추가 대상이면 30166이다.
- 호스트 노출 포트·컨테이너 내부 포트·외부 HTTPS 주소를 구분한다. DB 등 운영 도구 접근은 필요한 네트워크 범위로 제한한다.
- 실제 서비스 구성과 포트 사용 가능 여부를 확인한 뒤 최종 포트 목록을 ENV에 기록한다. 문서의 배정 규칙을 실행 중 리스너로 간주하지 않는다.
- 관리자 지정값을 제외한 필수 연결 값의 누락·빈 값은 실행 초기에 검증한다.
- 환경 설정에 실제 키·실제 서버 데이터 경로를 평문으로 저장하거나 커밋하지 않는다.

## 16. 필수 검수 사례

1. 동시 첫 로그인에서도 계정과 포트폴리오가 한 개만 생성된다.
2. 관리자 issuer·subject 중 하나라도 다르거나 두 값 모두 비어 있으면 관리자 권한이 없다.
3. 정지된 계정의 기존 세션·공개 상세 URL·AI·파일·PDF 경로에서 제한이 유지된다.
4. 임시저장 수정은 공개 반영 전까지 방문자 화면에 나타나지 않는다. 공개본은 서로 다른 편집 버전이 섞이지 않는다.
5. 숨긴 항목은 목록뿐 아니라 직접 URL·공개 API·AI 검색·메타데이터에서도 보이지 않는다.
6. 대표 스킬 11번째 추가는 API 직접 호출에서도 거부되고 일반 스킬의 정상 추가는 제한하지 않는다.
7. 개인 스킬 우선 표시가 다른 계정의 사전과 기존 프로젝트 연결을 손상하지 않는다.
8. 이미지 붙여넣기·드롭·재시도와 프로젝트 정렬·팝업 편집이 PC와 모바일에서 동작한다.
9. 템플릿 변경으로 데이터·순서·숨김·주소가 바뀌지 않고 다른 템플릿의 CSS가 간섭하지 않는다.
10. A 사용자의 AI 요청에서 B 사용자·초안·숨김 자료를 검색하거나 답변하지 않는다.
11. OFF·비공개·정지·재색인 도중 새 공개본 발생 시 오래된 결과로 접근 제한을 우회하지 않는다.
12. PDF의 버전·숨김·링크·한글·이미지·페이지 나눔을 실제 생성물로 확인한다.
13. 공개 페이지에 필요한 정보가 검색 가능한 HTML·메타데이터로 제공되고 초안·미리보기는 접근 차단된다.
14. 암호화 원본·평문 제외·필수 변수·포트·런타임 설정을 실제 실행 환경에서 별도로 확인한다.
15. 스킬 검색 결과 선택과 없는 스킬의 개인 등록이 일반 목록에 반영되며 중복·개인 항목 우선 표시 정책을 유지한다.
16. 아이콘 미선택·미지원·불러오기 실패에서도 약자 배지로 표시하고 스킬 연결을 유지한다. 개인 스킬 등록에는 외부 아이콘 URL 입력이 없다.
17. 방문자 스킬은 처음에는 대표만 보이고 더보기로 대표·일반 전체가 정렬되어 중복 없이 표시된다. 선택하지 않은 사전 항목과 숨긴 섹션은 보이지 않는다.
18. 히스토리 요약과 자세히, 프로젝트 요약과 템플릿별 상세 열기·직접 URL·뒤로 가기·외부 링크 클릭이 서로 충돌하지 않고 모바일·키보드에서도 동작한다.
19. 제목만으로 충분한 영역에는 불필요한 UI 설명이 없고 사용자가 작성한 요약과 필요한 입력·오류 안내는 유지된다.

## 17. 구현 전 기술 선택

추천에 위임된 프론트엔드·DB·빌드·세션·PDF 구성은 [Golden Path](GOLDEN_PATH.md)에 정리한다. 관련 소스는 [구조·분리 지침](../Agent.md#소스-구조와-분리-기준)을 따른다. 정확한 호환 버전, 서버 배치, 본문 첨부 허용 목록과 실제 플랫폼 연결은 초기 실행 구성에서 검증한다. 작업 순서와 착수 조건은 [개발 계획](DEVELOPMENT_PLAN.md)에 둔다. ENV 암호화·복호화와 로컬 Build/Push·운영 Pull/Up 스크립트는 각 프로젝트에 복사하여 구성한다. Windows PowerShell과 Linux/NAS·macOS 셸을 지원하고 운영은 서버 SOPS 복호화 또는 준비된 평문 ENV 중 명시적으로 선택한다. 최소 운영 파일 배치는 [공통 ENV 관리 지침](ENV_GUIDELINES.md)을 따른다. 사용자가 선택한 운영 환경은 AMD 계열 Linux/NAS의 Docker Compose이며 같은 Compose의 runtime 프로필에서 패키지 이미지로 실행한다. 상태창 DB의 백업과 네트워크 없는 임시 DB 복구 검사를 운영 준비 범위에 포함한다. 실제 서버 경로·PROD 값은 서버 확인 후 암호화 ENV로 관리한다.
